# YOLO を試す（ADR 0012、フェーズ 5b・6・7）

[English](yolo-quickstart.md) · 設計: [ADR 0012](adr/0012-yolo-mode.md) · 環境変数:
[configuration_ja.md](configuration_ja.md)

YOLO は、**押した時点から 6 時間**、チャットと Stage のターンでの**内部ツール**（ワークスペース・
書込み先の中のローカルファイル、Stira の記憶、`stop`、`handoff_to_user`）の『確認』を自動で
承認します。「外部もOK」（`STIRA_YOLO_ALLOW=external`、フェーズ 6）なら外部ツール（`web_fetch`、
`web_search`、`webhook_send`、`oauth_api_call`、`rss`、`speak`、`memory`、`perplexity_search`。
`http_request` も『しない』を変えていれば）の『確認』も自動で承認します。窓ごとに 200 回まで
（`STIRA_YOLO_MAX_EXTERNAL`）で、引数に秘密らしき値（URL の中のキー、ヘッダ、パスワードなど）が
あれば従来どおりカードが出ます。『しない』、保護された場所、ブレーカーの書込ブロック、CRITICAL、
実行系、MCP は変わりません（実行系が変わるのは、押したときに『実行系も含める』を選んだときだけ。6 節）。

**ボタンは既定で出ます**（[ADR 0012 追記 2026-10-24](adr/0012-yolo-mode.md)）: `STIRA_YOLO_ALLOW` も
設定画面で保存した「許可する範囲」も無ければ許可は `external` で、チャットのヘッダーと Stage に
`YOLO を開始` が出て、ダイアログに両方の範囲が出ます。押して確認するまで何も承認しません。
`STIRA_YOLO_ALLOW=off`（または設定画面の「許可する範囲: オフ」）でボタンが消え、何も変わりません。
既定では『実行系も含める』は出ません（6 節には自分で `external` を指定する必要があります）。

**YOLO より狭く:** 「同じツールで同じフォルダ・ホストをしばらく」なら、承認カードの「承認して、この
セッション中は同じ操作を許可」で足ります（1 つのツール × 1 つの対象、最長 2 時間、設定不要。
[allow-again_ja.md](allow-again_ja.md)）。窓が開いている間は YOLO が先に答え、継続許可が窓を開く・
延ばす・上限に数えられることはありません。

**YOLO が自動で承認するのは、方針が『確認』（毎回確認）のツールだけです**（#450）。『常に許可』は元から
確認が出ないので承認するものがなく、『しない』（使わない）は YOLO の間も実行されません。『確認』のツールが
1 つもなければ、窓を開いても何も自動承認されません。開始ダイアログは、選んだ範囲で自動承認の対象になる
ツールの数と名前を出し、0 個ならそう警告して、ツールの設定への導線を出します。まとめて設定するなら
`/settings#sec-tools` のプロファイル（*開発*: ローカルの書込みと `shell` を『確認』、*調査*: さらに
`web_fetch` / `web_search` も『確認』）を選んで保存します（[configuration_ja.md §5](configuration_ja.md#5-tool-configjsonツールルール)）。

## 1. サーバーを起動する（範囲を自分で選ぶ場合）

普通に起動すればボタンは出ます（上の既定）。範囲を自分で選ぶなら:

```sh
STIRA_YOLO_ALLOW=internal STIRA_PORT=5612 scripts/stira_ctl.sh start
# 前面で動かすなら: STIRA_YOLO_ALLOW=internal STIRA_PORT=5612 .venv/bin/python dashboard/stira_server.py
```

**設定画面からでも有効にできます（フェーズ 7c）:** 設定 →「YOLO（一時的な自動承認）」→
「許可する範囲」を「内部ツールまで」（または「外部送信まで」）→「YOLO 設定を保存」→ 確認にチェック
→ サーバーを再起動（`scripts/stira_ctl.sh restart`）。値は `gateway-config.json` の `"yolo"`
に保存されます。環境変数が設定されていればそちらが優先されます（画面には「環境変数で固定」と出ます）。
同じ画面の上限は再起動なしで次の窓から使われます。

ポート（`STIRA_PORT`）は空いているものを自分で選びます。Stage も使うなら `STIRA_STAGE=1`。
`internal` の代わりに `external` にすると、ダイアログに「外部もOK」も出ます。起動ログに
`YOLO allowance: internal (...)` と出ます（既定のときは 1 行 `YOLO: the Start YOLO button is
offered (default; ...)`）。時計を実測したプラットフォーム（現在は macOS）が
必要で、それ以外ではバッジに使えない理由が出ます。

モデルを呼ばずに試すなら: `STIRA_YOLO_ALLOW=internal STIRA_STAGE=1 STIRA_PORT=5612
.venv/bin/python tests/stira_yolo_harness.py /tmp/yolo-try`（メッセージを送るたびに、台本の
モデルがワークスペースに小さなファイルを 1 つ書きます。`search` を含むメッセージなら代わりに
`web_search` を呼びます。`STIRA_YOLO_ALLOW=external` で試してください。エンドポイント未設定なので
何も送信しません）。

## 2. 押す・確認する・見る

1. `/chat`（または `/stage/`）を開くと、ヘッダー（Stage では対話ボックスの縁）に
   **YOLO を開始** が出ます。
2. 押すと、何が変わるかの説明と範囲の選択、その範囲で自動承認の対象になるツールの数と名前
   （0 個なら警告）が出ます。**次へ(確認)**。
3. 確認ダイアログに範囲・要求 ID・終了予定が並びます。「内容を確認しました(いま自分が押した
   操作です)」にチェック（「外部もOK」ならもう 1 つ）を入れて **確認して開始**。どちらの段階でも
   取り消せば何も始まりません。
4. バッジが `YOLO 内部のみ · 残り 5時間 59分 · 自動承認 0/2000` と **YOLO を停止** になります。
   内部ツールの『確認』はカードを出さず、チャットのログ・Stage のログ・生ビューに 1 行ずつ
   `自動承認 (YOLO 内部): file_write #a3f2 — 1/2000` が出ます。「外部もOK」の窓ではバッジに
   `外部 3/200` も出て、外部ツールの行は `自動承認 (YOLO 外部): web_fetch #b4c1 — 38/2000 · 外部 3/200`
   になります（どこへ送ったかは出しません。監査には宛先ホストの鍵付きハッシュだけが残ります）。
   200 回を使い切るとバッジに「外部ツールは確認に戻りました」と出て、外部ツールのカードが戻ります
   （内部ツールはそのまま）。この行はページを再読み込みすると
   消えます（件数はバッジに残り、再読み込み後は「このページを開く前の自動承認: N 件」の 1 行が出ます）。
   読み込みの間に 20 件を超えた分は「…ほか N 件」の 1 行にまとまります。
   バッジの下の行は、窓の中で動いた**ツール呼び出し全部**の件数です（#448）:
   `ツール 7 回 (自動承認 3 / 常に許可 2 / 手動 1 / 拒否 1) · 上限は自動承認だけを数えます`。
   「常に許可」はカードが要らなかった呼び出し（規則が『常に』、または規則の無い読み取りなど）、
   「手動」は人がカードに答えたもの、「拒否」は『しない』・保護された場所・ブレーカー・人の却下などで
   実行しなかったものです。実行してエラーを返したものがあれば `· 失敗 N` が付きます。
   **上限（自動承認 2000 / 外部 200 / 実行 200）が数えるのは YOLO の自動承認だけ**で、常に許可・手動・拒否は
   上限に数えません（「自動承認 0/2000」のままツールが何回も動くことがあります）。数えるのはこの
   エージェントの全ターンの呼び出し（YOLO の対象外のターンのものも）で、`batch` は外側と中の呼び出しを
   それぞれ数えます。窓の外の呼び出しは数えません。同じ内訳（ツール名別・内部/外部/実行系別、ターン数）は
   `/api/yolo/status` の `window.tool_calls` / `window.turns` にもあります（件数だけ。引数・出力・
   コマンド・宛先は入りません）。呼び出しは数えた窓のものです: 実行中に窓が終わっても（その呼び出しで
   上限に達した、または停止を押した）、そのエラーは `last_end`（メモリ。`/api/yolo/status` と、
   次に読み込んだときの終了後のバッジ）の「失敗」に入ります。終了時に書いた `audit.yolo.ended` の行は書き換えないので、失敗が 1 件少ないことがあります。
   数え損ねはログに残すだけで、呼び出し・上限・終了は変えません。
5. ブレーカーが NORMAL でなくなると `一時停止中 (WARNING)`。NORMAL が 10 分続くまで
   『確認』はすべて確認に戻ります。終了の 10 分前にバッジで知らせます。延長はできません
   （終わったらもう一度押します）。

キーボード: Tab でボタンへ、Enter。ダイアログでは Space でチェック・選択、Tab でキャンセルと
確認ボタンへ、Esc で取り消し（フォーカスはボタンに戻ります）。

別のタブ（または別の画面）で開始・停止・解除した結果は、このタブに戻るか、ここで何か操作するまで
バッジに反映されません（何も動いていない間は状態を読みに行かないため）。

## 3. 止める

**YOLO を停止** は、確認待ち・開始処理中・実行中・一時停止中のどの状態でも、確認なしで効きます。
新しい会話（`/new`）、サーバーの停止、再起動でも窓は終わります（再起動で戻ることはありません）。
終了理由（「停止しました」「6 時間が経過して終了しました」「自動承認の上限に達して終了しました」
など）は **了解** を押すまでバッジに残ります。
窓が終わると、その窓を見ていたページのログに `YOLO の窓 ab12cd34 で動いたもの: ツール 7 回 (…) · ターン 2`
が 1 行出て、終了理由のバッジにも同じ内訳が残ります（次の窓まで `last_end` でも読めます）。監査の
`audit.yolo.ended` にも同じ集計（`tool_calls`、`turns`。件数だけ）が入ります。停止・期限・上限・
サーバーの停止（再起動の最初に起きる）のどれで終わっても、そのプロセスで動いた分が記録されます。
クラッシュや強制終了では終了の行そのものが書けないので、集計も残りません（ラッチ中になります。次節）。

## 4. 「ラッチ中」: 正常に終わらなかったとき

時計の異常、監査やマーカーの書込失敗、クラッシュのあとは、「前回の YOLO が正常に終わって
いません」と出て、新しい窓を開けません。何があったか（サーバーのログ、イベントストアの
`audit.yolo.*`）を確かめてから **ラッチを解除** を押し、確認にチェックを入れます。
時計の異常で終わったときは、`audit.yolo.ended` にどの判定が働いたか（`clock_check`）と比べた差
（`d_wall`、`d_boot`、`last_d_wall`、`last_d_boot`、`clock_slack_sec`。秒）が入ります。
「この画面からは解除できません」と出る場合は記録そのものを読めていません（データディレクトリの
`yolo-window.json` が壊れている・通常のファイルでない、またはイベントの鎖を検証できない）。
そのファイルを確認し（マーカーは消さない）、再起動します。起動時にもう一度判定します。

## 5. ホスト側で確認する（任意）

`STIRA_YOLO_HOST_CONFIRM=command`（macOS のデスクトップセッションなら `dialog` / `auto` も）に
すると、確認はページではなくホストで行います。押したあとバッジに「ホストで確認してください」と
残り時間（2 分）と取り消しボタンが出ます。サーバーのコンピューターの端末で
`stira yolo confirm <id>` を実行します（またはデスクトップのダイアログに答えます）。このときページ
での確認は拒否されます。各値が何を防ぐかは [configuration_ja.md](configuration_ja.md)。

## 6. 実行系も含める（任意、フェーズ 7）

`STIRA_ENABLE_EXEC_TOOLS=1` **かつ** `STIRA_YOLO_ALLOW=external` のとき、ダイアログに 3 つ目の選択肢
**実行系も含める (外部も含む)** が出ます。その窓では、確認が必要な（規則が『確認』の）`shell` と
`batch` もカードなしで実行されます。窓ごとに 200 回まで（`STIRA_YOLO_MAX_EXEC`）。秘密らしき値を
含むコマンド（`export TOKEN=…`、Bearer ヘッダ、URL の中のキー）はカードのままで、`cron` と
サブエージェントを起動するツール（`use_agent`、`think`、`swarm`、`graph`。Stira 自身の `delegate` も、
ADR 0016 フェーズ3 まではどの窓でも）もカードのままです。
`batch` は中の呼び出しを 1 件ずつ数え（`shell` を 1 つ含む `batch` で 200 回のうち 2 回）、
`batch` の中の `cron` やサブエージェントの呼び出しにもそれぞれカードが出ます。
確認ダイアログには 3 つ目のチェック「コマンドが確認なしで実行され、Stira の保護(保護された場所・
監査)を迂回しうることを理解しました」があります — **これは文字どおりの意味です**: コマンドは
サーバーの OS ユーザーとして動き、Stira の床や監査が守っているものを変えられます。どうせ 1 件ずつ
承認する作業にだけ使ってください。バッジは `実行系も含む · 実行 1/200`、行は
`自動承認 (YOLO 実行系): shell #c0de — 39/2000 · 実行 1/200` です（コマンドそのものは表示も記録も
しません。記録は引数の鍵付きハッシュだけ）。

オフラインで試すには: `STIRA_YOLO_ALLOW=external STIRA_ENABLE_EXEC_TOOLS=1 STIRA_STAGE=1
STIRA_PORT=5612 .venv/bin/python tests/stira_yolo_harness.py /tmp/yolo-exec` — その新しいデータ
ディレクトリでは `shell` と `batch` が『確認』になり、`shell` を含むメッセージで台本のモデルが
`/tmp/yolo-exec-sandbox` に `printf` を 1 回実行します。
