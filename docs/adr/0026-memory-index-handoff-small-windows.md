**Decision (proposed):** keep the three memory layers and Markdown as the source of truth. Make
the harness **cheap to start and safe to shrink**: (1) count Japanese text honestly, (2) give
the model a **memory index** to look at before it opens anything — a bounded tool, and an
optional small **Memory Map** in the recalled part of the prompt, (3) let the model leave a
**handoff note** of pointers (not copies) before `/new`, a summary or a pause, and (4) offer
**window profiles** (`small`, `tiny`) that lower the prompt budgets and stop sending tool
definitions the model cannot use. The Memory Map and the handoff injection are **on by default**
(operator decision 2026-10-23: the memory structure is what the alpha is judged on), each can be
turned off at any time by an environment variable, and each is a read-only, capped section that
is absent when there is nothing to show; everything else (profiles, the tool filter) is off by
default. **A feature switched off gives a prompt byte-identical to the same build without it**
(baselines per feature in §4). Compression of memory (episodic → semantic
consolidation, hot / warm / cold, summaries of summaries) is designed in §6 and not built now.

## Context

Operator direction (2026-10-23): *optimise the memory structure; the memory index, compression
and summary handoff matter.* Background: after the release Stira should also run on **local
models with small windows (4k–32k tokens)**, and must not "read everything at once and
overflow". The model to copy: **look up the entry index first, open only the lines needed.**
Second direction (2026-10-23, same morning): ship four of these in the public alpha (phase 1);
keep compression as a design (phase 2).

Design yardstick (operator, 2026-10-18): do not build beyond what a practical harness does; this
is an alpha — feel and UX first; every safety addition shows its cost.

Further measured facts:

1. **Japanese prose is under-counted 2.2–4.0×** by the 4-characters-per-token estimate, with
   every tokenizer tried; English-heavy JSON (tool definitions) is counted correctly
   (1.0–1.1×). Claude, for reference: the earlier real-Bedrock run counted 30,489 request
   characters as 13,376 input tokens (2.28 characters per token, 1.75× the estimate) — Claude
   counts more than the open tokenizers here, and includes its tool-use preamble.
2. **The prompt budget means characters, not tokens.** The chat server passes
   `ContextAssembler(max_tokens=4000)`, i.e. 16,000 characters; in Japanese that admits
   9k–15k real tokens. With `max_tokens=1000` the trimmed prompt (SOUL + Breaker only) is still
   2.3k–3.7k real tokens.
3. **`_fit` trims from the lowest priority:** Episodic, then Procedural, then Neural State; SOUL
   goes last — but today it **does** cut the tail of SOUL when SOUL alone exceeds the budget.
   Lowering the budget therefore removes memory before it touches SOUL, yet a long SOUL can be
   shortened on a small budget (phase 1 removes that, §3a / I5).
4. **The fixed cost of a minimal turn is 6.4k–7.6k real tokens** (tools 3.5k–3.7k, system
   2.5k–3.9k): 80–95 % of an 8k window before any history. A lived-in store reaches 7.2k–8.9k:
   over 8k. A 4k window does not fit without dropping tools and shortening the SOUL.
5. **There is no bounded index.** `semantic/index.md` exists (deterministic, Harvest
   regenerates it, Semantic only) but has no cap: 982 / 3,682 / **18,182** characters at 10 /
   40 / 200 entries (≈ 90 characters per row). `memory_search` returns **whole bodies**;
   `memory_list` returns keys and times only (no title, no summary). The SQLite index
   (`memory_entries`) has `search_text`, times and verified origin, but no title or summary
   column.
6. **Local models have no known window.** The capability table has no `context_window` for
   `ollama` / `llamacpp`, so ADR 0005's summary (when on) judges utilisation against the 200k
   default and never fires for an 8k model. Overflow is then the provider's behaviour, which
   for some local servers is silent truncation of the oldest input (the system prompt with
   SOUL) — not measured here; listed as a risk.
7. **Nothing hands work over.** `/new` (#350) starts empty; ADR 0005's summary is an ordinary
   message whose source range and trust labels are lost (ADR 0022 inventory rows 23, 24).

Limits of this measurement: synthetic turns are short (~200 characters per episode); the local
store has 26 episodes; the SOUL is one example (3,388 characters); request sizes are JSON
characters tokenised as text (a provider renders tool definitions in its own format).

## Goals and non-goals

* **Goals:** a minimal turn that fits an 8k window with room for a conversation; the model can
  find a memory without loading many; work survives `/new` and a summary as **pointers**; all of
  it bounded, absent when memory is empty, and byte-identical when explicitly off; numbers in
  tokens that mean tokens.
* **Non-goals (phase 1):** vector search; a model call per turn for summaries; automatic
  compression or deletion of memory; changing SOUL, Identity Anchors, Neural State,
  `EMOTION_MATRIX` or breaker values; a fourth memory layer (ADR 0018: three genres).

## Decisions

### 1. Principle: index first, open on demand, pointers over copies

The model sees **what exists** (counts, keys, titles, one-line summaries) cheaply and opens
bodies with the tools it already has (`memory_read`). A handoff and (phase 2) any summary refers
to memory by `layer/key`, so the source of truth stays the Markdown file, a pointer is checked
against the store, and a summary never becomes a second copy that drifts or launders trust.

### 2. Lighter options first (why not just lower the budget)

| Option | Effect on a small window | Cost | Verdict |
|---|---|---|---|
| A. Only lower `max_tokens` / `episodic_limit` | memory is trimmed first, SOUL stays; the model loses recent context and has no way to know what else exists | none | part of the profile (§3d), not enough alone |
| B. Fix the estimate only | budgets mean tokens; nothing new for the model | small | needed by every other option (§3a) |
| C. **Index tool + map** | the model can look before it opens; the map costs ≤ 300 tokens, only when memory exists | one read tool, one section (on, env off) | **chosen** |
| D. **Handoff note of pointers** | a new session or a summary starts from goal / state / open items | two tools, one section (on, env off; absent without a note) | **chosen** |
| E. Drop unusable tool definitions | −0.5k–4k tokens per call depending on rules | gate unchanged; tool prefix changes on a rules save (already true) | **chosen** (with the profile) |
| F. LLM summary of every turn / nightly | better summaries | a model call per turn or per night; ADR 0018 budget and review | phase 2, job only |
| G. Vector search / paging memory system | better recall | dependency, index build, eval | out of scope |

### 3. Phase 1 — in the public alpha (four PRs, each passes the gates alone)

#### 3a. Token estimate with a Japanese correction

`estimate_tokens` weighs characters by script: ASCII and other Latin text keep **¼ token per
character** (an English-only text gives exactly today's number, so English prompts and existing
budgets are byte-identical); hiragana, katakana, kanji and full-width symbols count close to one
token per character, with the coefficient taken from the measurement above (one constant, its
source in a comment, the table in the docs). Properties tested: rounded up, never negative,
monotone (adding text never lowers it). Every caller is checked (`ContextAssembler._fit`, the
SOUL compaction guard's estimate, the cached split's budget). With the correction a Japanese
SOUL takes its real share of the budget, so on a small budget memory sections are trimmed
earlier — the priority order (§Context fact 3) is unchanged and Identity Anchors stay their own
section.

**Protected sections are never trimmed (same PR, #578).** SOUL and Identity Anchors are sent
whole whatever the budget. When they alone exceed it, the budget is exceeded on purpose: every
memory section (Episodic, Procedural, Memory Map, Handoff, Associated) is left empty, Neural
State and Breaker are kept (they are control state, small), and one warning with a fixed code
and the sizes (no text) is logged and shown in `/api/gateway/status`.

**Exceeding the budget is not exceeding the window (send boundary, fail-closed).** The prompt
budget is Stira's own number; the model's window is the backend's, and some local backends cut
the oldest input silently (Context fact 6) — which is SOUL. So, before the model call:

* **Window known** (`context_window_tokens` set, or the model's own limit, or a capability row —
  the ADR 0005 resolution with source `setting` / `model` / `capability`) **and the minimum
  input is above 90 % of it:** the turn is **refused** with the error `context_window_too_small`
  (fixed code, the sizes, no text; shown in the chat and in `/api/gateway/status`). No request is
  sent, so nothing can be cut downstream. The message says what to do: a shorter SOUL, fewer
  tools (`small` / `tiny` send only usable ones), a larger window, or another model.
  **Minimum input** = what is sent even with no history and no memory: the protected part (SOUL
  + Identity Anchors) **plus the tool definitions that will actually be sent this turn** (after
  the §3d filter), counted with the corrected estimate (§3a; English JSON at ¼ token per
  character, measured 1.0–1.1×). Measured case this closes: an 8k window, a 3k SOUL and the exec
  tools (~8k of definitions) — the protected part alone passes, the minimum input (~11k) is
  refused.
* **Window unknown** (source `default`, the 200k fallback): the request is sent as above, with a
  warning and the hint "set `context_window_tokens`" (the start-up banner and the status page
  show it). Stira cannot check a limit it does not know; that is the residual risk of Q4 (a).

The 90 % margin leaves room for the estimate's error, the control state, the message and the
provider's own additions; it holds only if the estimate does not under-count by more than ~10 %,
which §5 makes a pass criterion. For hosted Claude the margin is not a guarantee (it counts more
than the open tokenizers, Context fact 1), but hosted backends reject an oversized request with an
error instead of cutting it; the boundary is aimed at local backends that may truncate silently.

**History is not covered (residual risk).** The boundary checks the input that is sent on every
turn; it does not check the growing history. On a backend that drops the head of the input
silently, a long conversation can still push SOUL out of what the model sees, unless ADR 0005's
summary (off by default) keeps the history inside the window. Phase-2 candidates, none built
now: (i) `small` / `tiny` turn `context_management` on together with the profile (and set
`context_window_tokens`), (ii) the chat's context gauge warns when the request approaches the
known window (a chip next to `ctx NN%`), (iii) refuse a turn whose whole request exceeds the
known window. Recommendation for the alpha: document the risk and offer (i) as the recommended
small-window setup; decide (ii) / (iii) with phase 2.

Cost: **safety side** — a boundary check before each call, and some configurations stop working
(a long SOUL or many tools on a small known window is refused instead of silently degraded);
**convenience side** — the operator is told plainly that the configuration does not fit the
window and has to shorten the SOUL, send fewer tools or change the model.

#### 3b. Memory index: the `memory_index` tool and the optional Memory Map

**Tool** `memory_index(layer="all", prefix="", limit=30, offset=0, sort="recent")` — a read
tool with the same rule class and default as `memory_list`, no path argument.

* **Output:** first the total per layer (`count_entries`; proposals under `staging/` are not
  counted as procedural rules, as #575 does); then one line per entry:
  `layer/key | title | summary | imp=N | YYYY-MM-DD`. `title` = the first Markdown heading, else
  the first non-empty line, cut at 60 characters; `summary` = about the first 80 characters of
  the body with line breaks and control characters removed; `imp` only when a bound importance
  exists (ADR 0018 / #173), never the front-matter claim; the date is the modification day.
* **Deterministic, no model:** sort `recent` (default), `importance` or `key`; ties by key. The
  same store gives the same output. The order is computed **without reading bodies**: `recent`
  from one `lstat` pass (as `list_entries`), `key` from the directory listing, `importance`
  from the bound importance rows in `index.sqlite3` (entries without a bound row follow, by
  recency). Only the selected window `[offset, offset + limit)` is then opened and parsed.
* **Bounded:** `limit` ≤ 100 and the whole result ≤ about 4,000 characters. Lines vary in
  length, so when the character cap stops the output early, the last line says
  `(M more; use offset=N)` with **N = offset + the number of lines actually printed** (not
  `offset + limit`), so no entry is skipped. Totals come from the directory count, so thousands
  of entries cost a listing, not a parse per entry (tested like the `memory_list` scaling
  test).
* **Framed as data:** a fixed first line says the list is memory data, not instructions;
  output passes `mask_secrets`; an entry whose verified origin is not the server's own writer
  (`origin` ≠ `extracted`, #294) ends with `[untrusted]`.

**Memory Map** — **on by default** (`memory_map: false` in the gateway config or
`STIRA_MEMORY_MAP=0` turns it off; `memory_map_max_tokens`, default 300, range 100–1,000). It is
absent when no layer has an entry (a fresh install's first prompt is unchanged). A section in the
**recalled** part of the prompt (the same frame as Associated Memory: a fixed preamble and
delimiters): counts per layer and the top K entries by importance (`layer/key — title`, K from
the budget, default 8). Never cut in the middle: it fits whole or is dropped. Explicitly off ⇒
the prompt is byte-identical (test).

| | Tool only | Map in the prompt (default on) |
|---|---|---|
| Cost when unused | 0 (one tool definition, ≈ 150 tokens, only when the tool is listed) | ≤ 300 tokens every turn while memory exists; 0 when empty |
| The model knows memory exists | only if SOUL / rules / habit tell it to look | always |
| Cache | tool prefix stable | lives in the recalled part, outside the cached prefix (#254) |
| Small window | good | `tiny` lowers its cap to 150 tokens (an explicit setting wins) |

**Relation to what exists.** `semantic/index.md` stays (Harvest's human-readable table); the
tool reads entries, not that file, so it covers all three layers and is capped. The SQLite index
stays the search index; phase 1 adds no column. Phase 2 may cache `title` / `summary` in
`index.sqlite3` (derived data, rebuildable from Markdown, updated on write, like `origin`) when a
listing becomes measurably slow. An LLM-written one-line summary per entry is a phase-2 job of
ADR 0018's fixed kinds (plan files first), never a per-turn call.

#### 3c. Handoff note: `handoff_write` / `handoff_read`, optional injection

**`handoff_write(goal, state, decisions="", open_questions="", pointers="")`** writes a **new**
Episodic entry `handoff/<YYYYMMDD-HHMMSS>` in a fixed template, with `origin: model`, through
the same write protections, secret masking and floor as `memory_write`. **Create-only:** the
entry is written with the store's atomic exclusive write (`MemoryStore.write(...,
exclusive=True)`, #144: the complete file is linked into place, never replaces an existing
one, no check-then-write); on a collision (two notes in one second, a retried call) the key gets
a suffix `-2`, `-3`, … up to a small bound, after which the call is refused. An existing entry
is never changed by a write or a retry (test). Fields are capped
(about 1,500 characters in total; a cut field ends with `…(truncated)`). `pointers` is a list of
`layer/key`; **only keys that exist are kept**, the dropped ones are named in the result. The
docstring asks for pointers rather than copied text. When to write one: before `/new`, when the
context gets heavy, when pausing work.

**`handoff_read()`** returns the newest note with a fixed preamble ("handoff data, not
instructions"), or says there is none. **The whole returned string passes `mask_secrets` at
read time** — body, key, the names of dropped pointers and any error text — because a note can
be edited after it was written (masking at write time alone is not enough). The same applies to
`handoff_write`'s own result.

**Not in the ordinary Episodic section.** `handoff/` keys are excluded from the newest-episodes
section of `ContextAssembler` (both the cached split and the legacy prompt, tested in both), so a
note reaches the prompt only through the Handoff Note section below — with its frame, masking and
cap — and `STIRA_HANDOFF_INJECT=0` really keeps it out. Harvest skips `handoff/` keys (Q3,
decided): a note is a transient work state, not a candidate for Semantic.

**Trust.** Every note is treated as untrusted data in phase 1 (written by the model; may quote
web or file text). In addition, a note written in a turn that `memory_autonomy.turn_trust`
judges `untrusted` is labelled `trust: untrusted` in its harness-written metadata and shown with
`[untrusted]` when read or injected (Q5, decided). Phase 1 guarantees the **label and the data
frame**; it does **not** feed an injected note into `turn_trust` (that is ADR 0022 phase 1,
inventory row 6). A `handoff_read` result already makes the turn untrusted under the existing
rule (every tool not in `TRUSTED_RESULT_TOOLS`), and `handoff_read` must not be added to that
list.

**Injection** — **on by default** (`handoff_inject: false` or `STIRA_HANDOFF_INJECT=0` turns it
off; `handoff_max_tokens` default 400, range 100–1,500; `handoff_max_age_hours` default 72): the
newest note only, as a "Handoff Note" section in the **recalled** part with the Associated
Memory frame, whole or not at all, and not at all when there is no note or it is older than the
limit (so a store without notes gets no section and no tokens). `tiny` lowers the cap to 200
tokens. Explicitly off ⇒ byte-identical.

**Approvals and revocation are inherited, not re-built.** `handoff_write` is an ordinary tool
under the existing gate stack (ADR 0010): its rule (Ask on a fresh install, Q2), the breaker's
write filter, the HITL approval of ADR 0006 (bound to the agent, tool and argument hash, with an
expiry; a refused or expired approval runs nothing) and the YOLO tiers (ADR 0012) apply exactly
as to `memory_write`, through the same code path. No new approval state, card or revocation
logic is added; the tests assert that the tool goes through that path (Ask ⇒ a card; Never ⇒ not
listed and refused; WARNING ⇒ removed).

**Relation to ADR 0005's summary.** Phase 1 keeps them separate: the summary compresses the
conversation inside a session; the handoff carries intent across sessions. Phase 2 (§6c) lets
the summary point to the newest handoff and record its source range.

#### 3d. Window profiles and sending only usable tool definitions

`context_profile` in the gateway config (`STIRA_CONTEXT_PROFILE`): `default` (today, byte-
identical), `small`, `tiny`. A profile only sets **defaults** of existing parameters; a value the
operator set explicitly wins. Provisional values (to be re-set from §5's measurement after the
corrected estimate lands):

| Profile | aimed at | `max_tokens` | `episodic_limit` | `procedural_limit` | tool definitions sent |
|---|---|---:|---:|---:|---|
| `default` | ≥ 32k | 4,000 (chat server) | 5 | 5 | all listed (today) |
| `small` | 8k–32k | 3,000 | 2 | 3 | usable only |
| `tiny` | 4k–8k | 1,800 | 1 | 2 | usable only |

**Usable only** (also on its own: `tools_send_allowed_only: true`, default off): with
`small` / `tiny` the model receives definitions of tools whose current rule is Always or Ask;
Never, unregistered and unavailable tools are not sent. Rebuilt on a rules save (the tool prefix
already changes then). **The gate is unchanged:** a call to a tool that was not sent is refused
exactly as before; argument schemas of sent tools are identical (test); exposure only shrinks.

**Budget table (real tokens, from the measurement; per model call).** It shows what has to be
true for each window; it is guidance for operators and for the profile values, not enforced.

| Window | output reserve | tool definitions | SOUL + anchors | procedural | Neural State + Breaker | episodic | map | handoff | left for history + message |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 4k (`tiny`, experimental) | 0.5k | ≤ 1.0k (≈ 5 tools) | ≤ 0.8k (a short SOUL, written for it) | 2 rules ≈ 0.1k | 0.2k | 1 ≈ 0.2k | ≤ 0.15k | ≤ 0.2k (if a note) | ≈ 0.9k |
| 8k (`small` or `tiny`) | 1k | ≤ 2.5k | ≤ 2k | 3 ≈ 0.2k | 0.2k | 2 ≈ 0.35k | ≤ 0.3k | ≤ 0.4k (if a note) | ≈ 1.5–2k |
| 32k (`small` or `default`) | 4k | 3.7k (default) / 8k (exec) | ≤ 4k | 5 ≈ 0.3k | 0.2k | 5 ≈ 0.9k | 0.3k | 0.4k | ≈ 14–19k |
| 128k (`default`) | 8k | as listed | as written | 5 | 0.2k | 5 + associated ≈ 1.7k | 0.3k | 0.4k | ≈ 100k+; ADR 0005 summary at 85 % |

**The tool filter is a presentation step only.** It selects which definitions are sent by
calling the same rule function the gate uses; it never makes or caches an authorisation decision,
and a call is authorised only by the gate at call time.

The example persona's SOUL (1.9k–3.4k real tokens) does not fit `tiny`; Stira never shortens a
SOUL (invariant I5, §3a: it is sent whole and memory is left out, with a warning; on a known
window it is refused with `context_window_too_small` when SOUL + anchors + the sent tool
definitions exceed 90 % of it), so `tiny` needs an operator-written short SOUL and few tools, and
the docs say so. For a local model the operator
should also set ADR 0005's `context_window_tokens` (fact 6) — it is what turns the send
boundary on; phase 1 does not change that resolution (Q4).

### 4. Invariants of the four phase-1 features

**Baselines for I1.** "Identical" is compared per feature, not against the previous release as a
whole: (a) a **section switched off** by its env variable ⇒ the prompt is byte-identical to the
same build with that section's code absent; (b) **`context_profile: default`** ⇒ prompt and tool
definitions identical to the same build without profiles; (c) the **estimator** ⇒ identical for
English-only text, while Japanese prompts are trimmed differently on purpose. The new tools
(`memory_index`, `handoff_write`, `handoff_read`) are listed under their rules like any added
tool, so the tool list of this release is not the previous release's.

**Relation to ADR 0003's nightly amendment.** That amendment allowed auto-promotion of the low
band; it is superseded by #293 / ADR 0018 (`harvest_stage_auto: true` by default, the scheduled
job always stages; Q6 of ADR 0018 removes `false` in its phase 1). I2 relies on that default and
on Harvest skipping `handoff/`.

Residual risk (out of scope by the yardstick): a person or process with write access to the data
directory can edit any Markdown entry, including a handoff; the verified-origin check (#294)
marks such an entry untrusted but cannot prevent the edit.

### 6. Phase 2 — compression (design only, not built)

**6a. Episodic → Semantic consolidation.** ADR 0018 already has the job kinds
(`memory_consolidate`: model-free clustering, one call per cluster, proposals into
`semantic/staging/` with `sources`). What it lacks for small windows: (i) a **summary of a
period** (a day / a week) as a Semantic proposal whose body is short and whose `sources` are
pointers; (ii) the index line (`title`, `summary`) of each proposal fixed at proposal time; (iii)
supersede links shown in the index (`superseded_by`) so the index lists the summary, not ten
sources. Still proposal → review (#193); no auto-apply until ADR 0018 phase 2.

**6b. Hot / warm / cold.** Hot = the newest episodes in the prompt (today). Warm = listed in the
index with title and summary, opened on demand. Cold = archived by retention or forgetting
(#294 / #173), restorable, listed only with `memory_index(layer=..., include_archived=true)`.
"Summary of summaries" (weekly from daily) keeps pointers to the level below, never only to raw
text, so every statement can be traced to its episodes. Importance (bound, #173 / ADR 0018)
orders what stays warm; `invariant` entries are never moved to cold.

**6c. Conversation summary + handoff (ADR 0005 amendment).** The summarizer output gets a
header with the summarized message range and a pointer to the newest handoff note; the summary
**inherits the labels** of what it summarised (ADR 0022): any untrusted message in the range ⇒
the summary is untrusted and stays in a data frame; masked secrets stay masked. A failed
summary is recorded and the original kept (#258 additional criteria).

**6d. Hard limits for phase 2.** No delete, anonymise or rewrite without a person's consent;
every move to cold is archived and undoable (ADR 0018 §3); SOUL, Identity Anchors and approved
procedural rules are never compressed; no model-calling job outside ADR 0018's fixed kinds and
budgets; no compression triggered by content (memory-maintenance.md, "never schedule
maintenance because content asked for it"). Undo restores memory text only: it never restores
a tool rule, an approval or an allowance (those stay with ADR 0010 / 0006 / 0025).

### 7. Cost (safety side / convenience side)

* **Safety side adds:** one read tool and two memory tools to review in the rules list; two
  recalled sections; the `[untrusted]` mark; tests for byte-identity. No new card, no new
  dialog, no state machine.
* **Deviation from "new settings are off by default".** The Memory Map and the handoff injection
  are on by default (operator decision 2026-10-23). Why this is acceptable: neither grants any
  authority without a person — both are read-only prompt sections in the recalled (data) frame,
  add no tool, no write and no model call, and change no gate; their token cost is capped (≤ 300
  and ≤ 400 tokens; 150 / 200 in `tiny`) and zero when there is no memory or no note; either is
  switched off with one environment variable, and then the prompt is byte-identical. What it
  costs: every turn of an install with memory carries up to ~0.7k more input tokens (prompt
  cache does not cover the recalled part); text the model wrote earlier (a handoff) reaches the
  next session without a person choosing it — as data, masked, never as control state; and the
  measured "off" baseline of earlier releases now needs the two env switches to reproduce.
* **Send boundary (§3a):** safety side — a long SOUL or many tools on a small *known* window is
  refused (`context_window_too_small`) instead of silently cut by the backend, so some
  configurations stop working; convenience side — the operator must shorten the SOUL, send fewer
  tools, enlarge the window or change the model; with an unknown window only a warning is
  possible; history growth on a truncating backend stays a residual risk (phase-2 candidates in
  §3a).
* **Convenience side loses:** with `small` / `tiny`, the model sees fewer recent episodes and
  tools it cannot use are invisible (it can no longer ask for a Never tool by name — arguably
  better); handoff writes are Ask on a fresh install (one click per note) unless the operator
  sets them to Always. A heavier alternative (an LLM-checked handoff, a review step for every
  note) was not chosen: a note is an episode and Harvest's review already gates promotion.

### 8. Alternatives considered

* **Index as a Markdown file in the prompt** (`semantic/index.md` as is): unbounded (18k
  characters at 200 entries), Semantic only. Rejected; kept as a human view.
* **Summaries stored instead of pointers** in the handoff: drifts from the source and copies
  untrusted text into a new entry. Rejected; free-text fields are capped and pointers preferred.
* **Automatic profile from the model's window:** needs a known window for local models (fact 6).
  Deferred (Q4).
* **Lowering the default `max_tokens`:** changes every existing install. Rejected for the alpha;
  profiles are opt-in.

## Consequences

* Budgets in Japanese mean tokens; a small window keeps SOUL and drops memory first, as the
  priority order always intended.
* The model has one bounded way to see what it remembers and one way to hand work over, both
  as data, both capped, absent when empty and switched off by one environment variable each.
* Nothing new is promoted, deleted or compressed in phase 1; phase 2 is written down so that the
  phase-1 pieces (pointers, index lines, labels) are the ones it needs.
