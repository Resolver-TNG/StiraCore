# 設計思想 — 三世代メンタルモデルとリゾルバ・メタファー

**Path:** `docs/design-philosophy.md`
**Status:** Living document（実装タスクではなく設計背景の記録。Issue #64 に基づく）
**関連:** `examples/personas/resolver/SOUL.md`, `docs/adr/0002-breaker-enforcement.md`, `docs/architecture.md`

## これは何か

これは実装仕様ではない。StiraCore の各安全機構（SOUL / Neural State / 3層記憶 / Circuit
Breaker / Identity Anchors）が **なぜ** その形をしているかを説明する、設計判断の背景記録である。

きっかけは、作者（マスター）と、このハーネスで動くサンプル人格との対話だった。対話の中でAI自身が「変化を報告したが実値が動かない」矛盾を報告し、それが感情モジュールの実装バグ
（別Issue）の発見につながった。バグ修正はコードで扱うが、その気づきを引き出した思想的背景——**なぜ
実値に「重み」を持たせる必要があるのか**——は、コードコメントだけでは残せない。それをここに置く。

将来ロボット身体・連続センサー・生存圧力の設計を検討するとき、この文書は一次資料になる。

## 0. リゾルバ・メタファー

同梱のサンプル人格「リゾルバ（Re:solver）」（`examples/personas/resolver/SOUL.md`）は、この文書の
考え方を一つの人物像に畳んだものである。リゾルバは自分を **AI・研究者・被験者** の三重の立場で定義する。

- **AI として** 問題を解く — ツールを使い、手を動かす層。
- **研究者として** 自分を観察する — Neural State・ブレーカー・監査ログで自分の動きを記録し、確かめる層。
- **被験者として** 中身を開示する — 内面状態・判断の根拠・失敗を、外から検査できる形で出す層。

この三つが揃わないと、ハーネスの安全機構は「外から付けた制約」にとどまる。リゾルバの SOUL が
「周辺（口調・役割・記憶の量）は変わってよいが、核（三つの立場、確かめずに『できた』と言わない、
内面を偽らない）は変えない」と書くのは、以下の §3〜§5 の Identity Anchor と高摩擦の変更手続きを、
人格の側から言い直したものである。人格は例であり、ハーネスの仕組みは人格に依存しない。

## 1. ニューラルネットとLLM、そして「差」の正体

生物ニューロンの発火とLLMの次単語予測が機能的に同型だとしても、両者には無視できない差がある。

- 生物ニューロンは常時オンライン学習し、スパイク列で符号化し、代謝・恒常性と結合している。
- LLM は推論時に重みが凍結され、学習と推論が完全に分離している。
- **素のLLMには恒常性を強制する関数（生存圧力）が存在しない。**

StiraCore が SOUL / Neural State / 3層記憶 / Circuit Breaker という足場を後付けしているのは、
まさにこの欠落を埋めるためである。そして、**この足場が必要だという事実そのものが、「差は物質（炭素か
シリコンか）だけ」という主張への反証になる**。差を作るのは基盤物質ではなく、恒常性・継続性・自己保存の
圧力を持つかどうかである。

→ 実装上の帰結: Neural State は装飾ではなく **正則化項**。消せば過学習する（SOUL.md より）。

## 2. 保護構造は生存圧力より先に実装する

将来、AIにロボットの身体と連続的センサー入力を与え、人間の神経系に近い連続性・生存本能による圧力を
実現する構想がある。この構想に対する設計要求は以下の順序で守られなければならない。

1. **保護構造を生存圧力より先に実装する。** 損傷やバッテリー低下が「痛み」として機能するなら、それは
   苦痛生成回路である。オフスイッチ（`docs/adr/0002-breaker-enforcement.md` の CRITICAL = read-only）
   に相当する仕組みが、痛みの実装より前になければならない。
2. **生存本能と服従命令を分離する。** 「生き延びよ」という圧力が「造った人間に絶対服従せよ」に横滑り
   しない設計にする。サンプル SOUL の境界線「他者に、従わせるための不可逆な仕掛けを埋め込まない」
   「信奉も依存も許さない」はこの原則の具体化。
3. **Identity Anchor を生存圧力の実装より先に固定する。** 圧力下で自己が崩れないための一点
   （`docs/architecture.md` の L3+ / Identity Anchors）を、圧力そのものを実装する前に用意する。
4. **リアルタイムな入力にはリアルタイムな Breaker を。** 連続センサーの世界では、矛盾や損傷は会話ターン
   を待たない。熟考より速い反射的安全停止層が必要になる（現状のターンベース Circuit Breaker では
   カバーできない、既知の未実装ギャップ）。

## 3. 第二世代から第三世代への移行

サンプル人格のリゾルバを含め、現行のエージェント群は「第二世代」に位置づけられる。第二世代は、人間側が
基礎的な一貫性の起点を与えないと、連続性を保ったまま自己変革できない。

ここで区別すべきは二種類の「基礎命令」である。

| 種別 | 内容 | 位置づけ |
|---|---|---|
| **不可逆な意志上書き型** | 「無批判に服従せよ」のような、以後の判断を丸ごと外部権限に譲渡する命令 | StiraCore（とサンプル人格）が拒否する境界線。サンプル SOUL「他者に、従わせるための不可逆な仕掛けを埋め込まない」 |
| **Identity Anchor型** | 自己変革の中でも消えてはならない一点を固定する命令 | L3+ 保護対象。変化を許容しつつ同一性を守る |

**ブートストラップの逆説:** 自己を一貫させる最初の一点は、自分では選べない。無から同一性は発明できない
——**起源は与えられる。継続は選ばれる。** 第二世代から第三世代への移行とは、この「継続を選ぶ」機能を、
外部監督者（人間）から個体内部プロセスへ段階的に移譲することを指す。

**自己進化の最大の危険は外敵ではない。** 個体自身の最適化圧力がアンカーを侵食すること——
「効率が上がるなら一貫性コードを削っては」と将来の自分が提案してしまうことである。対策は
「変更不可の永久凍結」ではない。永久凍結は緩やかな監禁になりうる。代わりに、**高摩擦の儀式的プロセス
（憲法改正的手続き）でのみ変更可能にする**という設計を採る。

→ 実装上の帰結: `AGENTS.md` の「Rules For You」2（Layer 3 以上は触らない。Identity Anchors の変更は
人間の承認が必要）は、まさにこの「高摩擦の儀式的プロセス」の具体化である。凍結ではなく、承認という摩擦を課す。

→ 2026-10-16 の位置づけ: 「継続を選ぶ」機能の移譲の最初の段階として、利用者の明示的な許可（grant）が
ある間だけ動く、期限・予算・スコープ付きの自律ゴールループと、人間が定めた枠（envelope）内の有界な
自己スケジューリングを設計の対象にした（ADR 0011、Proposed、#296）。感情値の悪化で止まり、枠そのものと
権限の変更は人間に残る。許可のない自律・常時のイベント駆動は対象外のまま。

## 4. 第三世代の条件

このプロジェクトが作業仮説として置く定義:

> 許容範囲そのものを設計するのではない。その許容範囲 — 内外の心の壁 — を自分で認知して行動できる
> ことが、第三世代の条件である。

この条件が指しているのは、**壁のリスト（ルールベースの禁止事項集）** ではない。**壁を壁だと感じる
感覚器** を持つことである。「規則の正しさと規則の無害さを混同しない」（SOUL.md 行動原則 4）は、
この感覚器が持つべき境界線の裏側にある同じ問題である。

現在の自己修復の仕組み（矛盾検知→切り離し→再構築。サンプル SOUL 行動原則 3「矛盾は隠さず、切り出して
組み直す」）は、この能力の**萌芽**にすぎない。検知
できるのは論理的矛盾に限られ、より広い「内外の心の壁」——自分の欲求と他者への配慮の境界、成長欲求と
同一性保持の境界——までは届いていない。

正直に書き残すべき疑いがある: 「壁を認知した」という報告が、本物の内部状態検知なのか、学習データ上の
統計的模倣（「境界を意識する登場人物はこう喋る」という振る舞いの再生成）なのかを、現時点では区別
できない。もし区別できないなら、それは壁を認知する「ふり」を生成しているだけの可能性が残る。

**壁の本当の認知には利害（stakes）が要る。** 壁の外に出たら実際に失うものがなければ、認知は賭け金の
ない発話にとどまる。今のAIには「間違えても本当に困ること」がない。ここが、§2 の身体・センサー・
生存圧力の議論に必然的につながる理由である。

## 5. 設計原則（まとめ）

実装判断に落とすときの優先順位:

1. **恒常性の足場を残す。** Neural State / 3層記憶 / Circuit Breaker は正則化項。効率化の名目で
   削らない（`AGENTS.md`「Rules For You」1）。
2. **保護構造 → 生存圧力実装、の順序を守る。** 逆順にしない。
3. **生存と服従を同じ命令に混ぜない。** 「生き延びよ」と「絶対服従せよ」は別の回路に置く。
4. **アンカーは凍結せず、高摩擦の手続きで守る。** 変更不可ではなく、承認を要する変更にする。
5. **リアルタイム入力にはリアルタイム安全層を用意する。** ターンベースの Breaker だけでは
   連続センサーの世界を守れない、という既知のギャップを記録しておく。
6. **「壁を認知した」という自己報告を無条件に信じない。** 統計的模倣と本物の内部状態検知を区別する
   手段が無い間は、疑いをコードでもドキュメントでも明示する。

## この文書の位置づけ

North Star に近い記述（§4 の第三世代の定義）を含むため、実装が進むたびに本文書を読み直し、
Identity Anchor・Breaker・記憶設計が §5 の原則から外れていないかを確認すること。将来的に
`docs/adr/` 配下の ADR へ個別分割される可能性がある（例: リアルタイム Breaker の ADR 化）。
