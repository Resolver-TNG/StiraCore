# 処理ごとのモデル（`task_models`）

[English](task-models.md)

会話のターンとは別に、モデルを呼ぶ補助の処理があります: コンテキスト管理の要約（#258）と、
長いツール結果を求めに応じて要約する処理（#585、`web_fetch(summarize=True)`）。既定ではどれも
**会話のモデル**（`inherit`）を使い、これまでと同じに動きます。処理ごとに別のモデル（例: 同じ
プロバイダの小さいモデル）を指定できます。

## 処理

| 処理 | モデルを呼ぶもの | ツール |
|---|---|---|
| `tool_summary` | `web_fetch(url, summarize=True, focus=…)`（#585、[tools/web-fetch.md](tools/web-fetch.md)）。出力は未信頼のデータ。会話のモデルを引き継ぐときも記録する。 | なし |
| `context_summary` | コンテキスト管理の会話要約（#258、オプトインの `context_management`）。 | なし |

ルーティングに載せないもの（独自の設定がある、または会話のモデルが要る）:

| 呼び出し元 | 載せない理由 |
|---|---|
| LLM 蒸留器（`distiller_mode: "llm"`） | 独自のモデル設定（`distiller_model_id`、ADR 0018）がある。1つの呼び出しに設定が2つあると食い違う。 |
| `delegate` の子エージェント（ADR 0016） | ツールを実行する。別モデルにすると費用だけでなく「何が動けるか」が変わる。別の判断が要る。 |
| 刺激分類器（Sokudan / ルール） | 会話モデルではない（ローカル分類器またはルール）。 |
| モデル切替・接続テスト・評価ランナー | それ自体が会話モデルの選択、または独自の `--model` を持つ CLI。 |

## 設定

処理ごとの優先順: 環境変数 `STIRA_TASK_MODEL_<処理名>`（空でない値）> gateway の `task_models` >
`inherit`。起動時に読みます。

```json
{"task_models": {"tool_summary": "global.anthropic.claude-haiku-4-5-20251001-v1:0"}}
```

```sh
STIRA_TASK_MODEL_TOOL_SUMMARY=global.anthropic.claude-haiku-4-5-20251001-v1:0
```

値:

* `inherit`: 会話のモデル（既定）。
* モデル ID だけ: **会話と同じプロバイダ**のモデル。会話のエンドポイント（`base_url`）・キーの変数
  （`api_key_env`）・組織の変数・リージョンを引き継ぐので、データの行き先は会話と同じです。
* `provider:model`（例: `ollama:qwen3:8b`）: 別のプロバイダ。会話のエンドポイントやキーの設定は
  引き継ぎません（Bedrock はリージョンだけ）。そのプロバイダの認証情報が設定済みであること
  （`credential_status` が設定済みと判定: SDK の既定のキー変数、AWS 認証チェーンの手がかり、または
  ローカルサーバー）。Stira は新しい認証情報を探しません。

## フェイルクローズ

* 起動時、次の場合はサーバーが起動しません（終了コード 2。固定のコードと処理名だけを出し、値は出さない）:
  処理名または `STIRA_TASK_MODEL_*` の変数が未知の処理（`unknown_task`）、モデルが能力表に無い
  （`unknown_model`）、プロバイダの SDK が無い（`provider_unavailable`）、認証情報が未設定
  （`credentials_not_configured`）。
* 指定したモデルが呼び出し時に失敗したら、**その処理**を失敗にします（`model_failed` と理由コード）。
  会話のモデルや別のモデルで再試行しません: 費用とデータの行き先が、利用者の知らないうちに変わらない
  ようにするためです。`context_summary` では SDK の要約失敗時の挙動どおり、会話は短くなりません
  （溢れからの回復中なら、そのターンはエラーで終わります）。
* ツールを取らない処理に、ツール定義つきの呼び出しが来たら、モデルに届く前に拒否します
  （`tools_not_allowed`）。会話のモデルを引き継ぐ（`inherit`）ときも同じです（会話のモデルを同じ境界の
  内側で使い、それ以外の送信内容は変えない）。
* 環境変数名は大文字の `STIRA_TASK_MODEL_<処理名>` と完全に一致すること。別の綴り
  （`STIRA_TASK_MODEL_tool_summary`、小文字の接頭辞など）は黙って無視せず、起動を拒否します。
* 固定コードのエラーには、プロバイダや生成処理の元の例外をつなげません。元のメッセージ（キー・署名付き
  URL・ページ本文を含みうる）がトレースバックやログに出ないようにするためです。

## 記録

指定したモデルへの呼び出し1回ごと（`tool_summary` は会話のモデルを引き継ぐときも）に、ターンイベント
`task_model.call`（`/observability` に表示）、監査行 `audit.task_model.call`、ログ1行を残します: 処理名・プロバイダ・モデル ID・入出力トークン・状態（`success` / `error` /
`refused`）・理由コード。本文や URL は残しません。

## 設定画面

**出力上限とコスト → 処理ごとのモデル** に、読み取り専用で表示します: 処理ごとの実効モデルと、
その出所（環境変数・設定ファイル・`inherit`）。次の起動を拒否する保存済みの設定は、サーバーの稼働中も（稼働中の行の下に）コードつきで表示します。
変更は `gateway-config.json` か環境変数で行い、再起動で反映します。

## 残るリスク

ルーティングは、運用者が管理するファイルと環境変数での運用者自身の選択です。それらを書き換えられる
攻撃者や、同じ OS ユーザーでコードを実行できる攻撃者は範囲外です。
