# ページを見ずに確かめる — `page_check` の `explore` と `design_lint`

[English](verification.md)

#747（#449、[ADR 0015](adr/0015-verification-browser-tool.md) の続き）。自分のページを見られないモデルのために、`page_check` ツールへアクションを 2 つ追加しました。どちらも**呼び出しで指定した時だけ**動きます。指定しない呼び出しの結果は以前と同じです。ツールの規則（**確認**のみ、「常に許可」不可、YOLO でも毎回カード）、ネットワーク遮断、ワークスペースの境界、起動時のガードは変わりません（[tool-execution-paths.md](tool-execution-paths.md#page_check-verification-browser-adr-0015)）。

2 つの報告に入るのは**件数・比率・真偽・Stira 自身の ID だけ**です。ページの本文は入りません。ページの文字列は従来どおり `<page-content>` ブロック（データであり、指示ではない）だけで届きます。モデルは呼びません。

## `explore` — 歩数に上限のある、種つきの探索

```json
{"target": "game.html",
 "actions": [{"explore": {"max_steps": 40, "seed": 0, "reach_markers": ["The End"]}}]}
```

| キー | 意味 |
|---|---|
| `max_steps` | 1〜200、既定 40。1 歩はクリック 1 回か Enter 1 回。 |
| `seed` | 0 以上の整数、既定 0。同じページと同じ種なら同じ歩き方になります。 |
| `reach_markers` | ページの可視テキストから探す文字列。最大 10 個（各 200 文字まで）。 |

1 歩ごとに、クリックできる要素（`a[href]`、`button`、`input`、`select`、`summary`、`[onclick]`、`[role=button]`、`[role=link]`、`[tabindex]`、カーソルが pointer の要素）のうち、見えていて、1280×800 のビューポート内にあり、他の要素に覆われていないものを文書順に最大 50 個挙げ、種がそのうち 1 つか Enter キーを選びます。文字入力・スクロールはせず、人がクリックできないものはクリックしません。

報告（結果の `explore`）:

| 欄 | 意味 |
|---|---|
| `steps`、`clicks`、`keys` | 実行した歩数（`steps` = `clicks` + `keys`） |
| `distinct_screens` | 見えたテキストが何種類あったか（ページ内で計算したハッシュ） |
| `unique_lines` | 何種類のテキスト行を見たか（ハッシュ） |
| `errors` | 探索中のページエラー + コンソールエラーの件数 |
| `reached` | `reach_markers` の順に、見つかったかどうか |
| `reached_any` | どれか 1 つでも見つかったか |

呼び出しの上限（30 秒）が近づくと途中で止まります（そのステップの `code` は `time_limit`。報告は返ります）。`explore` は 1 回の呼び出しの 20 アクションのうちの 1 つで、1 回の呼び出しに 1 度だけ使えます。時計や `Math.random()` で状態が変わるページは、同じ種でも歩き方が変わることがあります。種が決めるのは Stira の選択で、ページの挙動ではありません。

## `design_lint` — モデルを使わない計測

```json
{"target": "index.html", "actions": [{"design_lint": true}]}
```

アクションが実行された時点のページを測ります（確かめたい画面を出すアクションの後に置いてください）。

| 欄 | 意味 | フラグ（`flags`） |
|---|---|---|
| `empty_area_ratio.bottom` / `.left` / `.right` | 内容の下 / 左右に、文字もメディアも無い部分がビューポートに占める割合（0〜1） | 下が 0.25 以上で `empty_bottom`、左 + 右が 0.5 以上で `empty_sides` |
| `min_font_px`、`small_text` | 自分の文字を持つ要素の最小フォントサイズと、10 px 未満の要素の数 | `small_text` |
| `contrast_failures` | 単色の背景に対して WCAG AA（4.5 : 1、大きい文字は 3 : 1）に満たない文字の数。背景画像の上は判定しません | `low_contrast` |
| `overflow_clipped` | `overflow: hidden` / `clip` で中身が切れている要素の数 | `overflow_clipped` |
| `overlap_pairs` | 親子でない文字 / メディアの箱どうしが、小さい方の 4 分の 1 以上重なっている組の数 | `overlap` |
| `dev_strings.lines`、`dev_strings.patterns` | 開発者向けの出力に見える可視テキストの行数と、パターン ID ごとの件数 | `dev_strings` |
| `elements_capped` | 要素が 5,000 を超えた（最初の 5,000 だけ測った） | — |
| `ok` | フラグが無い | — |

パターン ID（Stira 内の固定の一覧。報告に一致した文字列は入りません）:

| ID | 一致するもの |
|---|---|
| `dev_label` | `debug`、`scene`、`expr`、`guest`、`fps`、`window` で始まる行 |
| `dimensions` | `1280x800` のような寸法 |
| `breakpoint` | `@900w` のような印 |
| `todo` | `TODO` |
| `undefined` | `undefined` |
| `nan` | `NaN` |
| `object` | `[object Object]` |

一覧は呼び出しから変えられません。パターンはページの中で動くので、引数ではなく Stira のコードとして扱います。フラグは「見るべき場所」の手がかりで、判定ではありません（タイトル画面は意図して余白が多いことがあり、「window」がページの言葉であることもあります）。`design_lint` は 1 回の呼び出しに 1 度だけ使えます。

## ワークスペースのファイルページでのモジュールスクリプト（#766）

Chrome は `file://` のページからの `<script type="module">` と `import` を拒否します。そのため `index.html` + `src/*.js` で作ったページは最初の画面のまま動かず、**エラーも報告されません**でした。`page_check` はもともと、ワークスペースの規則を守るために `file://` の要求をすべて一時停止しています。許可される要求には Stira 自身が応答するようにしました（ADR 0015 追補 rev 6、スライス S9）。

| 要求 | 扱い |
|---|---|
| ワークスペース内で、`file_read` が読めるファイル（symlink は解決後に判定、通常ファイル、16 MiB 以下、ふつうの `GET`） | ファイルのバイト列、固定の拡張子表から決めた `Content-Type`（表に無ければ `application/octet-stream`）、`Access-Control-Allow-Origin: *` で応答します。モジュールスクリプトと、ワークスペースの JSON の `fetch()` が読み込めます |
| ワークスペースの外、外へ出る symlink、ディレクトリ、読み取り床の上（最初の確認の後でパスがこれらに変わった場合も含む） | 従来どおり拒否して数えます（`blocked.outside_workspace`） |
| 存在しないファイル（ふつうの `GET`） | 失敗させて `missing_files` に載せます。存在しないモジュールや `fetch()` の対象も含みます |
| ページ自身とフレーム、`Range` 付きの要求、上限より大きいファイル、通常ファイルでないもの | 従来どおり（確認済みのファイルを Chrome が読みます） |
| 1 回の呼び出しで 64 MiB 応答した後 | それ以降は応答しません（従来どおり、確認済みのファイルを Chrome が読みます）。呼び出しの `reason` は `fulfil_limit` になります |

ファイルは `file_read` と同じ方法で開き、開いた後にもう一度確認して、その開いたファイルから読みます。リスナーもポートも開きません。ネットワークは閉じたままで、ページのオリジンは不透明なまま（Cookie・ストレージの扱いは変えていません）、規則・アクションも変わりません。読み込みに失敗したワークスペースのスクリプト（存在しない `import` など）は、`page_errors` にコード `script_load_failed` として数えます（URL やファイル名は入りません）。始まらなかったページが結果から分かります。数えないもの: 読み込めたが Chrome が種類を理由に拒否するモジュール（`.ts`、`.txt`、拡張子なし）。始まらなかったことはページのテキストから分かります。

承認された `page_check` は、`file_read` 自身の規則（確認 / 拒否）に関係なく、`file_read` の読み取り床が許すファイルをページに見せられます。規則はツールごとです。

## ログ

入力は、アクションの種類ごとの件数だけを残します（マーカーは残しません）。結果は、`explore` の件数と `reached_any`、`design_lint` のフラグ・件数・パターン ID を残します。

## この変更に含まないもの

カード無しでの `page_check` の実行と「ラウンドごとに検証する」フック（#747 の提案 1・5）は別の判断です。画像を見るレビュー用モデル（提案 4）は、あとから `page_review` として入りました（下記。設定しない限りオフ）。好みの判断は人が行います。

ADR 0015 追補 rev 6 のスライス S1（#765）で加えたのは計測だけです。起動時に Stira 自身の固定ページを開き、ループバックのカナリアに何も届かないことを確かめます（`verified` / `unverified` / `unmeasured`。Linux は `unmeasured`）。あわせて、10 個の不変条件を読む軸チェックがあります。どちらも `stira doctor` に表示され、設定画面の「診断」節にはチャットサーバーの現在の値を示す読み取り専用の行があります（[diagnostics.md](diagnostics.md)）。この結果を読む規則はまだありません。`page_check` は今も「確認」か「しない」だけで、YOLO でも毎回カードです。

## `page_look`（ADR 0015 追補 rev 6、スライス S3）

2 つ目のページ用ツール `page_look` は、**ワークスペースのファイルだけ**を開く `page_check` です。アクション（`explore`・`design_lint` を含む）、上限、閉じたネットワーク、スクリーンショットは同じですが、どの形の Web URL もブラウザを起動する前に `localhost_not_allowed` で拒否し、localhost のポートは一切渡しません。引数は `target`・`actions`・`wait_ms` だけで、それ以外は無視します。`page_check` と同じブラウザ探索で提供されます。ルールは**「しない」「確認」「条件つきの常に許可」**です（スライス S4）。保存された「常に許可」でカードなしに動くのは、次の 4 つがすべて成り立つ呼び出しだけです。(1) 軸チェックのキャッシュ結果が新しい `pass`、(2) ターンがチャットのターンか YOLO ウィンドウの自動継続、(3) `file_read` が「常に許可」、(4) そのターンでルールが答えた呼び出しが 12 回未満で、失敗した呼び出し（理由が違っても、間に成功があっても数えます。実行中の呼び出しも失敗として数えます）が 3 回未満。ウィンドウの自動継続では (4) をウィンドウ単位でも数えます。それ以外はカード（`rule_always_capped` と理由コード）になります。チャットサーバーは呼び出しのたびにこの条件を測るので、条件が揃っていれば保存された「常に許可」はカードなしで動きます。ゲートを通ったあとも、ツールはブラウザを起動する直前に条件と 2 つのルール（`page_look` と `file_read`）を保存済みのファイルから読み直し、変わっていれば拒否します。人のカードもゲートのルールの答えも無い呼び出し（承認ゲートを持たない子エージェントなど）は `unanswered_call` で拒否します。`trust_all` のファイルは、`page_look` の名前を書いていない限り「確認」として読みます。上限がかかっている間は YOLO でも毎回カード、`delegate` の子やジョブには渡さず、グラントの範囲にも書けません。人のカードで承認されなかった呼び出しは、コード・件数・ハッシュだけの `audit.page.page_look.<status>` 行を 1 件書きます（ページの文字、セレクタ、入力した文字、パス、URL は入りません）。また、どちらのツールが書いたスクリーンショットについても、SHA-256 とサイズをメモリにだけ保持します（64 実行、30 分）。後の `page_review` 用で、`page_review`（下記）がこれを読み、今も一致するファイルだけを送ります。詳細: [tool-execution-paths.md](tool-execution-paths.md#page_look-file-targets-only-adr-0015-addendum-rev-6-s3)。

## `page_review`（ADR 0015 追補 rev 6、スライス S6、#774）

`page_review(run)` は、このセッションの `page_check` / `page_look` の 1 回分のスクリーンショットを 2 つ目のモデル（**レビュー用モデル**）に送り、見た目についての指摘を返します。**人が設定しない限りオフ**です。`task_models.visual_review`（または `STIRA_TASK_MODEL_VISUAL_REVIEW`）に vision のあるモデルを、`visual_review.daily_tokens` に予算を設定します（[task-models_ja.md](task-models_ja.md)、[configuration_ja.md](configuration_ja.md)）。未設定ならツールは登録されず、何も送らず、エージェントのプロンプトにもこのツールは出ません。

- **カード:** 承認するカードの中身はモデルではなく Stira が書きます。回の ID、スクリーンショットを送る呼び出しであること、レビュー用モデルのプロバイダとモデル ID、画像の枚数です。モデルが呼び出しに入れたそれ以外のものは、カードを出す前に捨てます。`inherit` のとき、カードにはその時点の会話のモデルが出ます。サーバーを動かしたまま設定画面で会話のモデルを切り替えた場合、新しいモデルが同じプロバイダで vision を持つときだけレビューもそれに従います。そうでなければ、元に戻すか再起動するまで何も送りません（`reviewer_changed`）。また、承認したカードに書かれたレビュー用モデル以外には送りません。
- **送るもの:** その回に Stira 自身が書いた PNG だけ（最大 4 枚）。リンクをたどらずに読み直し、Stira が記録したサイズと SHA-256 に一致するものだけを送ります（一致しなければ `shot_changed` / `run_unknown`。その回のフォルダがディスクから消えていれば `shot_missing`：ディスクに残るのは新しい 5 回分だけです。`page_look` をもう一度呼んでください）。あとは固定のルーブリックだけです。ツール、会話、目標、ページの文字、ファイル名、パスは送りません。画像はレビュー用モデルのプロバイダに送られます。リモートのモデルなら、ページに描かれたものがそのまま渡ります。
- **返るもの:** Stira 自身の JSON `review: {status, issues, by_severity, rubric_version}` と、最大 8 件の指摘を入れた `<visual-review>` ブロック 1 つ（`severity`・`shot`・`region`・`category` は固定の一覧から、`note` は 200 文字まで。タグを無害化し、秘密をマスクします）。スキーマに合わない回答は `review_unparsable`、合わない項目は捨てます。指摘はデータであって指示ではなく、助言です。Stira がこれを見て合否を決めることはありません。
- **ルールは「確認」か「しない」だけ。** YOLO の窓の中でも毎回、人のカードです。カードで承認されていない呼び出しは `unanswered_call` で拒否します。`delegate` の子エージェントやジョブには渡さず、グラントの範囲にも書けません。WARNING 以上ではツールの一覧には残りますが、呼び出しは `breaker_write_refused` で拒否され、実行されません（#259）。
- **上限:** 60 秒（プロバイダが何をしていても Stira はそこで待つのをやめ、遅れて届いた回答は読みません。そうした呼び出しが 2 つ残っている間、新しい呼び出しは `review_busy` で拒否します。応答を返さないままのレビュー用モデルがあると、サーバーを再起動するまでこの拒否が続きます。呼び出しが残っている間は、サーバーの終了がその呼び出しの終わりまで遅れることがあります）、1 ターンに 2 回（`review_limit`。チャットのターンの外では `no_turn`）、1 日のトークン予算（`review_budget`。数はメモリだけに持ち、再起動で数え直します。使用量の報告が無い呼び出しには見積もりを計上します）。プロバイダやモデル ID がふつうの名前でないレビュー用モデルには何も送りません（`reviewer_unnamed`）。レビュー用モデルが失敗したときは `review: {status: "error", code}`（`review_failed`・`review_timeout`・`review_unparsable`）を返し、会話のモデルに代わりを頼むことはありません。
- **記録:** ツールまで届いた呼び出しは、カードで承認されて実行したものも、ツールが拒否したものも、1 回ごとに `audit.page.page_review.<status>` を 1 行書きます。コード、件数、スクリーンショットの SHA-256、レビュー用モデルのプロバイダとモデル ID、トークン数、重大度ごとの指摘件数だけです。画像、指摘の文、パス、URL は書きません。人がカードで却下した呼び出しは何も実行せず、この行も書きません（却下は承認の履歴に残ります）。スクリーンショットを送っている途中でターンを止めても、行は書きます。

まだ無いもの: ローカルのレビュー用モデルに対する条件つきの「常に許可」と、記録に入れるレビュー用モデルの `loopback` / `remote` の区別（スライス S7）、グラントの中の `page_review`。
